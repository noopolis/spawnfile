# CLI progress reporting

Persist bounded status and cost projections even without the optional viewer.
Never write prompts, articles, tool payloads, test-case identities or optimizer
feedback into the shared progress run. Immutable trial evidence keeps its original
storage permissions. Incomplete attempts keep observed usage and explicit gaps.
Failure reports retain a validated development-only view and protected diagnostic
references. Their cost projection includes all observed calls without test identities.
Replay verifies trial manifests with no sealed-test authorization; changing a case
label in an index or report must never grant access to a sealed trial.

Exercise generation failure, duplicate completion, settled success and replay of
persisted projections. Displaying progress never triggers inference.

Observed tool counts deduplicate native call IDs across dispatch and completion;
receipt-only traces count without inventing dispatches or complete coverage.
Reset identities per trial and expose only the count, never tool payloads.

`experiment.failed` publishes only an adapter-redacted startup reason when one
exists, plus the durable path of the redacted startup-diagnostics blob. The raw
error string stays a protected evaluator blob; the progress stream never carries
it.

When a diagnostic names an operator-only capture, the failure line names that
path too. It is the last account of a failure whose bytes could not be published,
and a path is not content.
