# Candidate Resources

Owns versioned instruction, skill, supporting Markdown and example file trees.

- Map source files from existing projects into a candidate without requiring a
  project rewrite. Preserve references, native destinations and editable/locked
  files or sections. Ordinary Markdown is first-class; templates are optional.
- Rendering is separate from DSPy component exposure and native installation.
  Installed, supplied, loaded and followed are different evidence claims.
- Never edit locked identity, access policy, fixture truth or rubric resources.
- Record source/rendered hashes and candidate lineage; reject unsafe paths,
  accidental overlap and undeclared edits before dispatch.
- Test multi-file reference preservation and mutate locked regions to prove edits
  are rejected. Do not add a template engine before its contract is agreed.
