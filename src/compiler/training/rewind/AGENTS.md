# Training Rewind

- `contract.ts` owns strict materialization, leak and task-clock documents and their generated schemas; the recording barrel owns moment records.
- `history.ts` is the only boundary for reading history files, logs and retained bytes; every path must be lexically and physically contained. Reuse recording wake/moment parsers, volume landing readers, and deployment resource lookup through their barrels.
- `deployedResource.ts` scopes fallback pins to the compiled agent and declaring node. Import one deployment log under `deployments/`, retaining its canonical original identity without reading that external path. Inexact activation/rollback pins remain approximate; a present but unavailable pin never silently becomes selector-at.
- `select.ts` and `inputs.ts` resolve original attempts, examples and compiled input identities; `recordInput.ts` isolates per-input recording failures. Dataset `at` matches wake time; `effectiveAt` is the original startedAt and owns all cuts, clocks and leak bounds.
- `types.ts` defines input identities, declarations and per-kind contexts/results; `index.ts` exports the public materializer and pure selection/cut helpers.
- `git.ts` owns resources; `gitProcess.ts`, `gitHistory.ts`, `gitTree.ts`, and `gitArchive.ts` isolate argv execution, containment, blob trees, and raw feed trees; `recordedCommit.ts` verifies full recorded IDs name commit objects without peeling.
- `feed.ts`, `memory.ts`, and `volumes.ts` own input reconstruction. `snapshotManifest.ts` requires Daimon completion markers and verifies full trees; `memorySchemas.ts` validates ledger events. Mneme generations are unsupported; seq:0 is exact empty.
- `feedContent.ts` verifies plain git revisions and re-extracts for independent byte acceptance; retained copies must match. Prepared revisions prove provenance only: always approximate, never compared to a directory content digest.
- `moltnet.ts` dispatches stores; `moltnetJson.ts`, `moltnetSqlite.ts`, `moltnetSqliteData.ts`, and `moltnetSchemas.ts` own snapshots, copied databases, SQL decoding, and strict native shapes.
- `materialize.ts` stages all inputs and publishes only after the independent disk reader in `leakCheck.ts` accepts them.
- `leakFiles.ts`, `leakGit.ts`, and `leakInputs.ts` inspect disk metadata, every git object, and native payloads independently of materialization decisions. `leakGitPayload.ts` compares raw output-repository blobs to the worktree and checks index stat times; `leakLayout.ts` enforces closed native layouts. `leakProvenance.ts` reopens source repositories read-only using disk commit receipts, checking type and both raw dates without the producer's guard and re-exporting bundle `source.trees` for byte comparison. Discover unexpected `.git` directories/gitfiles and bare repositories throughout every input; only the materialized git resource repository is allowed.
- `instant.ts` compares parsed nanosecond instants; `timestamps.ts` stamps metadata without following symlinks.
- `taskClock.ts` separates top-level harness JSON, libfaketime child offsets, and clock-aware child variables: one offset owner per process. Relative signed seconds preserve milliseconds and the shared anchor; trial preparation supplies LD_PRELOAD and a dot-decimal numeric locale. Timeouts remain real.
- Adjacent tests use local temporary repositories and fixtures. Never use Docker, production hosts or network fetches.
- `fixtures.test-helper.ts`, `snapshotFixtures.test-helper.ts`, and `git.test-helper.ts` build disposable real projects and repositories; package emission excludes them.
- Selector-at git history is approximate: committer dates cannot prove when a commit reached a ref. Feed-rule approximation cannot reconstruct freeze holds.
- Reuse P2 effective input identity resolution. No input may silently use present-day data.
- Feed/bundle extraction reads raw blobs, never `git archive` or attribute-driven transformations. Preserve symlinks for the escape check; refuse gitlinks. Recorded commits must be full lowercase 40/64-hex IDs verified as commit objects, including retained feeds.
- Guard every selected git/bundle/feed commit's author and committer dates before choosing output bytes, including retained/prepared feeds. Record the selected commit in the moment/identity; local pins or git-backed overrides without a history entry also record their repository path for independent acceptance.
- Validate each non-overridden input's recorded commit IDs in every same-agent/same-wake earliest-attempt copy before accepting that input, even when pin precedence omits those fields from selection comparisons.
- Validate memory JSONL structure locally; rewind never imports Mneme or ships an index/audit state. Checksum verification is skipped because persisted normalized events cannot recover the original JSON checksum input (`node_modules/@noopolis/mneme/dist/identity/ids.js:15-17`, `dist/store/store.js:249-274`).
- Mneme 0.1.1's index is rebuilt from the ledger before every index read, not on open: `node_modules/@noopolis/mneme/dist/runtime/runtime.js:86-87` (embedding recall), `node_modules/@noopolis/mneme/dist/kernel/kernel.js:152-153` (search), and `:207-208` (locate). A ledger-only materialized bank is complete.
- Inspect atime and mtime from metadata captured before payload reads, then restore captured access times without hiding existing future atimes.
- Preserve negative source epochs with Date/numeric-string filesystem times; recheck the final renamed bundle. Trial at/effectiveAt must be within 1970 through 9999 before materialization.
- Generated inputs spanning repositories refuse: this history contract carries one commit per resource. Never claim that one repository proves another repository's bytes.
- `recordedBundle.ts` requires digest-matching retained tars for exact bundles and independently checks extracted bytes; source reconstruction is approximate. `leakFeed.ts` proves late publication metadata against record/window history.
- Keep modules under 400 lines, use named/barrel exports, and never import Mneme internals.
- The public SQLite inspector audits the entire store regardless of room/sender filters, including cursor timestamps, and returns filtered messages ordered by stored timestamp text then ID. It reports findings rather than silently cutting messages; unknown objects refuse.
- Each inspected `orderedMessages` entry also carries `appendIndex`, the store-local SQLite `rowid`, before filtering. Larger values mean later appends; gaps are allowed. This is not a timestamp or a durable cursor across store rewrites (such as rewind/VACUUM). Consumers can select newest N by append position, then sort those messages by timestamp; the inspector's timestamp/ID order is unchanged.
- Inspector results also expose all registration/network/actor IDs, active room/network/member IDs, and IDs with noncanonical credentials (`token:<agent-id>` is canonical), independent of message filters. Never expose credential values. A sidecar refusal returns empty projections with a finding; callers must reject findings before trusting counts or IDs. Room labels/policies and expected identities stay caller-owned.
