# Authoring Examples

Owns readable integration examples used to refine Paideia's YAML authoring surface.
These are Markdown proposals, separate from executable task corpora in evals/.

- Group examples by project or coherent scenario family, with a reading-order README.
- Keep source mappings, cases, criteria and dataset semantics together. Reference
  external project inputs; do not copy private corpora, credentials or runtime state.
- Mark proposed fields and missing fixtures explicitly. YAML syntax acceptance is
  not schema validation, adapter support or evidence of a successful agent run.
- Keep each document focused and under 400 lines. Add nested guides and CLAUDE.md
  symlinks as responsibilities grow; inherit the root development rules.
- Verify relative Markdown links, fenced YAML syntax and existing source references.
- Do not implement code or configuration before authoring approval. Do not mount
  these evaluator-facing examples, rubrics or held-out answers into subject workspaces.
